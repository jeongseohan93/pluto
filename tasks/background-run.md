# 백그라운드 실행 — 발사 프로세스의 터미널 분리

## 배경 (실측)
터미널 창을 닫자 running 중이던 slice가 사망 (8/21). 재개 시도는
stale lock에 거부됨 — pid는 죽었는데 lock이 남아 수동 삭제 필요
했다. 에픽은 몇 시간 무인 진행이라 이 구조로는 불가.

## 요구사항
1. 분리 발사: 발사 시 파이프라인 본체를 터미널과 분리된 프로세스
   로 실행 (Windows·macOS 모두). 발사한 터미널/앱을 닫아도
   파이프라인은 계속 진행
2. 상태 관전: 기존 관전(watch·앱 패널)은 상태 파일·로그 기반
   이므로 그대로 동작해야 함 — 분리 후에도 진행 상황이 보일 것
3. stale lock 자동 인수: lock의 pid 생존을 엔진이 검사 —
   죽은 pid면 lock을 자동 인수하고 로그 1줄 남김 (수동 삭제 종료)
4. 명시적 중지 수단: 분리된 실행을 사람이 멈출 방법 제공
   (aidev 명령 또는 앱 버튼 — pid 기록 기반)
5. 기본값 논의: 분리 실행을 기본으로 할지 옵션(--detach)으로
   할지 plan에서 근거와 함께 제안

## 하지 않는 것
- 서버/데몬 상주화 / 원격 접속 / UI 신규 화면 (기존 패널 재사용)

## Done Criteria
- 발사 → 터미널 종료 → slice가 완주까지 진행 (fake로 검증)
- 죽은 lock 자동 인수 + 로그 / 중지 명령 동작
- 기존 watch·앱 관전 정상 / 기존 pytest 전량 통과
