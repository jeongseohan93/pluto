# 그래프 엔진 2단계 — 브리핑 생성기 (상차림)

## 배경 (설계 원칙)
"에이전트는 찾지 않는다. 좌표로 요청한다. 좌표는 그래프가 안다."
1단계로 Function DB 완성 (1189 함수, 명세 68%, 조회 동사 4종).
이제 엔진이 세션 발사 전에 DB를 선조회해 브리핑을 차리고
프롬프트에 동봉한다 — 에이전트의 '탐색' 행동을 소멸시키는 본체.
실측 근거: plan 탐색 20-59턴, implement 재탐색 $2-4/slice,
Repeated reads ×5-11 (2026-08-15~18 계기판).

## 요구사항

### 1. 브리핑 생성기 (엔진, 세션 0)
- 시점: plan/implement/amend/repair 세션 발사 직전, 엔진이 생성
- LOD 3단 축척:
  · 저해상(전역): repo 요약 — 모듈별 함수 수, 핵심 진입점(callers
    상위 N), 디렉터리 구조 한 줄씩. 토큰 상한 두고 압축
  · 중해상(관련부): requirement/plan 텍스트에서 추출한 키워드와
    매칭되는 함수들 — 이름+기능 한 줄+좌표 (매칭 방법은 plan에서:
    단순 문자열/식별자 매칭이면 충분, 임베딩 금지 — 마법 없음)
  · 고해상(scope): plan 이후 단계에만 — plan이 명명한 파일/함수의
    전체 명세 레코드 + 본문 발췌(라인 범위로 추출) + 호출/피호출
- 브리핑 말미에 조회권 안내 고정 문구: "이외는 aidev graph
  show/callers/calls/summaries로 요청하라. 파일 통읽기 전에 조회 우선."
- 산출물: 브리핑을 slice 디렉터리에 md로 저장 (프롬프트 동봉 +
  파일 보존 — 재시도·amend가 재사용)

### 2. 재사용 후보 절
- implement 브리핑에 한정: scope 함수들과 이름/기능 유사한 기존
  함수 목록 ("이미 있는 것" — 재발명 방지). 유사 판정은 단순하게
  (이름 토큰 겹침 수준), 과최적화 금지
- 프롬프트 규약 문구: "기존 함수 재사용 우선. 유사 기능 신설 시
  사유 명시. 통합 리팩토링은 금지."

### 3. 캐시·신선도
- 브리핑 생성 전 graph가 stale이면(dirty 표시 존재) 증분 갱신 먼저
- 프롬프트 배치: 불변부(전역 저해상)를 앞, 가변부(scope 고해상)를
  뒤 — 프롬프트 캐시 적중 순서
- 같은 커밋+같은 scope면 브리핑 재사용 (재생성 스킵)

### 4. 스위치
- front matter `briefing: off` — 완전 비활성 (실측 A/B용 + 탈출구)
- 기본값: on

### 5. 계측
- 브리핑 토큰 수를 계기판/RESULT에 기록 (상차림 비용의 가시화)
- 세션이 graph 조회 동사를 쓴 횟수 기록 가능하면 기록 (예외 경로
  발생률의 원천 — 불가하면 plan에서 사유 명시)
