\## 요구사항



\### 1. verify 단계 — test 세션의 엔진화

\- test 단계에서 에이전트 세션 제거: 엔진이 test\_commands 직접 실행

\- PASS → state 기록 후 종료 (세션 0, 비용 0)

\- FAIL → `failure.md` 자동 생성 후 진단 처리(§2)

\- failure.md 규격: 실행 명령/exit code/실패 테스트 목록(파일:라인

&#x20; +assert 메시지 한 줄)/traceback 요약(전문은 로그 경로 링크)/직전 커밋



\### 2. 진단 등급제

\- 실패 규모로 분기 (임계값은 plan에서 제안):

&#x20; 소형(실패 N개 이하) → 진단 세션 없이 failure.md만 물려 재시도

&#x20; 대형 → 진단 에이전트 소환, 산출물 `diagnosis.md`

&#x20; (원인 한 줄/수정 방향/관련 파일:라인) → 재시도 프롬프트에 주입

\- 재시도 한도 초과 시 failure.md+diagnosis.md가 사람 보고 자료



\### 3. 출력 다이어트 — implement 개발 중 검증

\- implement의 테스트 실행 결과를 엔진이 가로채 요약본만 세션에 전달

&#x20; (실패분만: 파일:라인+메시지. 성공 목록은 개수만)

\- 구현 방식(훅/래퍼)은 plan에서 결정



\### 4. Write 차단 — 기계 강제
